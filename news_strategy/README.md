# News-driven crypto strategy — прототип

Рабочий прототип методологии из обсуждения: применение теории вероятностей
и статистики к новостному потоку о криптовалютах для построения
торгового сигнала. Демонстрирует полный конвейер на синтетических данных
(без внешних API и ключей) — от новости до risk-adjusted бэктеста.

## Быстрый старт

```bash
cd news_strategy
pip install -r requirements.txt
python generate_sample_data.py   # генерирует data/prices_sample.csv и news_sample.csv
python run_pipeline.py           # прогоняет весь пайплайн и печатает отчёт
```

## Структура

```
news_strategy/
├── generate_sample_data.py   # синтетические цены + новости (для демо/тестов)
├── run_pipeline.py           # оркестратор: связывает все модули в один прогон
├── src/
│   ├── sentiment.py          # лексиконный сентимент-скорер (§2.2 из обсуждения)
│   ├── bayesian.py           # байесовское обновление P(рост | признак) (§2.1)
│   ├── event_study.py        # CAR + t-тест значимости эффекта новости (§2.3)
│   ├── kelly.py               # сайзинг позиции по дробному критерию Келли (§2.7)
│   ├── monte_carlo.py         # risk of ruin / max drawdown симуляция (§2.6)
│   └── backtest.py            # событийный бэктест: сигнал -> PnL -> equity
└── data/                       # сгенерированные CSV (в .gitignore, если больше не нужны)
```

## Что показывает прогон на синтетических данных

1. **Event study** отделяет новости, которые статистически двигают цену, от
   шума — в примере значим только тип `hack` (p ≈ 0.0004), у остальных типов
   эффект в пределах шума при данном объёме выборки. Это ожидаемо: у
   встроенной синтетики разный `mean_shock / noise` ratio по типам.
2. **Байесовская модель**, обученная на train-периоде, комбинирует тип
   новости и сентимент текста в единый признак и даёт калиброванную
   апостериорную вероятность роста для test-периода.
3. **Бэктест** входит в сделку только когда `posterior_up` уверенно отходит
   от 0.5 (`confidence_threshold`), размер позиции — дробный Kelly от
   оценённой вероятности победы.
4. **Монте-Карло** на распределении реализованных доходностей сделок даёт
   вероятность разорения и перцентили просадки — то, на основании чего
   калибруется допустимый риск на сделку, а не "на глаз".

## Как переключить на реальные данные

Интерфейсы модулей спроектированы так, чтобы заменить источник данных не
трогая остальной пайплайн:

- **Новости**: замените `generate_sample_data.py` на загрузчик из
  [CryptoPanic API](https://cryptopanic.com/developers/api/), Twitter/X API
  или RSS-парсер CoinDesk/CoinTelegraph. Нужен только DataFrame с колонками
  `timestamp`, `event_type` (или своя таксономия категорий), `text`.
- **Цены**: замените на выгрузку через `ccxt` (REST API Binance/Bybit) —
  нужен DataFrame с `timestamp`, `close` на нужном таймфрейме (5m/15m).
- **Сентимент**: замените `LexiconSentimentScorer` на обёртку над
  FinBERT/CryptoBERT (см. docstring в `src/sentiment.py`) — интерфейс
  `score(text) -> float` остаётся тем же.

## Известные ограничения прототипа (важно перед реальным использованием)

- **Разреженность признаков**: комбинация `event_type + sentiment_bucket`
  даёт много редких категорий, которые сильно сглаживаются к prior
  (Лапласовское сглаживание в `BayesianNewsModel`). На реальных данных нужно
  либо больше истории, либо иерархическая байесовская модель с backoff на
  уровень `event_type` при недостатке данных по полной комбинации.
- **Backtest упрощённый**: нет проскальзывания, частичного исполнения,
  реалистичной книги заявок — только фиксированная комиссия тейкера.
  Для реальной торговли нужен полноценный backtesting-движок
  (например, `vectorbt`, `backtrader`) с учётом ликвидности инструмента.
- **Look-ahead bias**: `generate_sample_data.py` по построению не содержит
  утечки будущего, но при подключении реальных источников проверяйте, что
  `timestamp` новости — момент её публичной доступности, а не момент
  индексации вашим скрапером.
- **Multiple testing**: `event_study_by_type` тестирует несколько типов
  новостей одновременно — при большом числе категорий добавьте поправку
  Бонферрони или контроль FDR (`statsmodels.stats.multitest`), иначе часть
  "значимых" эффектов — ложные срабатывания.
- **Устаревание сигнала**: эффект новости, который сегодня статистически
  значим, может исчезнуть за недели по мере того как рынок его
  арбитражирует — модель нужно периодически переобучать и валидировать
  заново на свежих out-of-sample данных, а не полагаться на разовую оценку.

## Расширения (не реализованы в этом прототипе)

- Hidden Markov Model для режимов рынка (`hmmlearn`) — экзогенная
  переменная сентимента влияет на матрицу переходов между режимами.
- News velocity (интенсивность потока новостей как пуассоновский процесс)
  как отдельный признак для детекции всплесков волатильности.
- Market-model event study (регрессия на BTC-бету) вместо локальной
  средней — точнее для альткоинов с высокой корреляцией к BTC.
