# Paper Trading Agent

Агент, торгующий в реальном времени **виртуальными деньгами** — реальных
ордеров на бирже не размещает и не может разместить (в коде физически нет
вызовов к authenticated-эндпоинтам бирж, только публичное чтение котировок).
Решения принимает исключительно на основе данных, которые сам успел
пронаблюдать в потоке — без подглядывания в будущее.

## Гарантии (что агент НЕ делает)

- Не использует и не запрашивает API-ключи биржи.
- Не импортирует и не вызывает ничего, что размещает реальный ордер.
- Не торгует с плечом, не открывает шорты (упрощение для paper-режима).
- Стратегия получает только `price_history` — буфер, который сам агент
  накопил по ходу опроса; это гарантирует отсутствие lookahead-bias,
  типичного для бэктестов "задним числом".

## Быстрый старт (без доступа в интернет — симулированный фид)

```bash
cd paper_trading_agent
pip install -r requirements.txt
python run_agent.py --data-source simulated --symbol DEMOUSDT \
    --interval 1 --max-iterations 200
```

Лог каждой итерации пишется в `state/trade_log.csv`, текущее состояние
портфеля — в `state/portfolio.json` (обновляется на каждом шаге, можно
смотреть параллельно с работающим агентом).

## Live-режим (реальные котировки биржи, всё ещё виртуальные деньги)

```bash
python run_agent.py --data-source live --symbol BTCUSDT --interval 15
```

Источник `live` — публичный REST-эндпоинт Binance `ticker/price` (без
авторизации). Работает на машине с доступом в интернет к `api.binance.com`;
в этой песочнице сетевая политика блокирует исходящие запросы к биржам —
поэтому для проверки в текущем окружении используется `--data-source
simulated`, а `live` нужно проверять там, где сеть разрешена (локально,
на VPS и т.п.).

Для непрерывной работы (24/7) запускайте через `systemd`, `screen`/`tmux`,
`nohup` или как контейнер — без `--max-iterations` цикл идёт бесконечно,
пока не будет остановлен (Ctrl+C или сигнал процессу).

## Архитектура

```
run_agent.py            # CLI: собирает компоненты, запускает TradingAgent.run()
src/
├── market_data.py       # источники цены: BinancePublicDataSource (live) / SimulatedDataSource
├── portfolio.py          # PaperPortfolio -- виртуальные cash/позиция/сделки, JSON-снапшот
├── strategy.py            # SmaCrossoverStrategy -- сигнал только по уже увиденным ценам
├── risk.py                 # RiskManager -- сайзинг, стоп-лосс/тейк-профит, дневной лимит убытков
└── agent.py                 # TradingAgent -- главный цикл: цена -> сигнал -> риск -> сделка -> лог
```

## Параметры риск-менеджмента (см. также `crypto-trading-guide.md` в корне репозитория)

| Флаг | По умолчанию | Смысл |
|---|---|---|
| `--risk-per-trade-pct` | 0.02 | базовая доля кэша на вход, масштабируется уверенностью сигнала |
| `--stop-loss-pct` | 0.03 | закрыть позицию при просадке от цены входа |
| `--take-profit-pct` | 0.06 | закрыть позицию при прибыли от цены входа |
| `--daily-loss-limit-pct` | 0.05 | остановить открытие новых позиций при дневной просадке капитала |

Приоритет в цикле агента: **стоп-лосс/тейк-профит уже открытой позиции
всегда проверяются раньше нового сигнала стратегии** — так агент не
проигнорирует управление риском ради нового входа.

## Проверено в этой сессии

- 80 итераций на `SimulatedDataSource` (низкая волатильность) — 1 полный
  цикл buy → sell по сигналу SMA, лог и `portfolio.json` корректны.
- 300 итераций при повышенной волатильности — все три ветки выхода
  сработали: `stop_loss`, `take_profit`, `signal_flat`.

## Ограничения и что нужно доработать перед реальным использованием капитала

- **Стратегия — учебный пример.** SMA-пересечение на одном активе без
  учёта объёма/новостей/режима рынка не является готовой прибыльной
  стратегией. Для комбинации с новостным сигналом см. `news_strategy/` в
  этом репозитории (`BayesianNewsModel`, `event_study.py`) — интерфейс
  `Strategy.generate_signal(price_history) -> Signal` спроектирован так,
  чтобы можно было подставить туда байесовский сигнал. Риск переобучения,
  устаревания сигнала и поправка на multiple testing — все предостережения
  из `news_strategy/README.md` применимы и здесь.
- **REST-поллинг, не WebSocket.** Для по-настоящему низкой задержки на
  реальном live-режиме лучше подключить WebSocket-стрим биржи вместо
  периодического REST-опроса — сейчас это самый простой вариант, работает
  надёжно, но не минимизирует задержку.
- **Один актив, без диверсификации.** Текущая версия ведёт позицию по
  одному символу; расширение на портфель из нескольких активов потребует
  отдельного риск-бюджета на актив (см. диверсификацию в
  `crypto-trading-guide.md`).
- Это остаётся симуляцией: реальное проскальзывание, частичное исполнение
  и реальная книга заявок не смоделированы (комиссия учтена как фиксированный
  процент). Прежде чем переходить к реальным деньгам, нужен более
  реалистичный backtesting/forward-testing период и отдельное решение о
  переходе на реальное исполнение — это не входит в scope этого агента.
